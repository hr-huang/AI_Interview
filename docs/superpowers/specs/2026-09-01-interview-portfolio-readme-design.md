# 面试作品型 README 设计

## 目标

把仓库首页从“完整技术说明书”改造成面向技术面试官的项目主页。面试官应当能够：

1. 在 30 秒内看懂产品解决什么问题、主要用户是谁；
2. 在 3 分钟内看到一条真实产品链路和关键工程难点；
3. 按需继续阅读架构、检索校准、测试和本地运行方式；
4. 从截图、演示和可复现命令中验证项目并非概念稿。

## 受众与叙事顺序

主要受众是招聘 AI Agent、LLM 应用工程和后端工程岗位的技术面试官。README 采用“产品结果先于内部实现”的顺序：

1. 品牌首屏：项目名、一句话定位、事实徽章、导航入口；
2. 真实演示：一张主视觉或短 GIF，展示产品而非装饰图；
3. 30 秒理解：`JD + 简历 → 审核计划 → 动态面试 → 证据报告`；
4. 核心工程亮点：Planner、Supervisor、Scenario RAG、Evidence Gap、确定性评分；
5. 一段真实动态追问案例，解释系统为什么不是固定题库；
6. 架构与数据流；
7. 快速运行与配置；
8. 校准、测试、技术栈、项目结构和交付边界。

当前 README 中较长的模型边界、配置表和项目结构应下移或折叠。内部规模数字只有在解释能力时才出现，不作为第一屏卖点。

## 视觉素材

所有核心素材必须来自当前项目真实页面，不使用无关的网络配图。

素材目录固定为：

```text
docs/assets/readme/
```

计划产出：

- `hero-assessment.png`：最能代表产品结果的桌面端主视觉；
- `workflow-create.png`：企业输入 JD 与简历；
- `workflow-plan.png`：面试计划审核与调整；
- `workflow-interview.png`：候选人逐题作答；
- `workflow-report.png`：雷达图、总评与证据追溯；
- `product-tour.gif`：由上述真实页面构成的短演示，控制体积并保证 GitHub 可直接展示。

若录制完整 MP4，则 README 只提供链接；第一屏仍使用经过压缩的 GIF 或 PNG，避免 GitHub 页面加载过慢。截图中不得出现真实 API Key、个人路径或敏感候选人信息。

## 首屏设计

首屏使用居中标题和一句话定位，但保持职业化，避免大量 emoji：

```text
衡鉴 Evidence Hiring

从 JD 与候选人简历生成可审核的动态面试，
并让每项能力结论都能追溯到候选人的原始回答。

[产品演示] [快速运行] [系统架构]
```

徽章只展示仓库中能够验证的事实：Python、LangGraph、React、FastAPI 和 CI。仓库没有 LICENSE 和已发布 Docker 镜像时，不展示 License 或 Docker Pulls 徽章。

## 内容边界

README 必须明确当前聚焦 `ai_application_engineering / 2026-H2`，但不以否定式清单占据主要篇幅。边界信息压缩到靠后位置：

- 已实现：JD/简历解析、计划审核、动态问答、Scenario Module RAG、证据评分、报告追溯；
- 暂未声称：多岗位平台、生产级多实例 Secret Store、语音或虚拟人面试。

不编造在线 Demo、Docker 镜像、准确率、下载量或许可证。测试数字必须从本次验证结果更新，不沿用历史快照。

## 技术亮点表达

技术亮点用“问题 → 设计 → 可验证结果”表达，而不是堆技术名词：

- 静态题库无法根据回答改变路径 → Evidence Gap 驱动 Supervisor 追问；
- RAG 容易让模型自由决定考点 → Supervisor 先锁定 Requirement，RAG 只选择合适业务场景；
- LLM 直接评分不可追溯 → Evidence、RequirementAssessment 与 ScoreEngine 分层；
- 自定义模型配置容易串线或泄露 → 评估级运行时隔离与内存态 BYOK；
- 检索“感觉不错”不可证明 → 固定校准集、Top-1/Top-3 与 forbidden diagnostics。

## 快速运行

README 提供恰好两条路径：

1. 演示模式：启动前后端后直接访问冻结演示报告，不调用付费模型；
2. 真实评估：配置 `.env` 或页面 BYOK，输入自己的 JD 和简历走完整链路。

所有命令必须在干净环境中验证。Windows PowerShell 作为主命令环境；不承诺尚不存在的一键 Docker 启动。

## 验收标准

- README 第一屏能够看到定位、入口和真实产品视觉；
- 至少四张截图覆盖完整企业评估链路；
- 不包含 API Key、个人绝对路径或候选人敏感信息；
- 所有徽章、规模数字、测试结果和功能声明均能由仓库事实支持；
- 快速运行命令可复制执行；
- Mermaid、表格、相对图片链接在 GitHub Markdown 中有效；
- 长配置与目录树使用 `<details>` 折叠；
- 不修改业务逻辑，不调用付费 LLM，不把截图采集变成新的产品功能。
