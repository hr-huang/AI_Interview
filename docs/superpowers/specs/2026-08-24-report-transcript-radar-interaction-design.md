# 完整面试记录与雷达交互优化设计

## 目标

让演示评估和真实评估共用同一套可追溯报告结构，并解决中等宽度下能力雷达与匹配边界的视觉压叠、雷达标签过小以及交互不明显的问题。

## 产品信息架构

报告中的两类信息保持分离：

- **完整面试记录**：按时间顺序展示所有面试轮次，包括问题、候选人完整回答、题型、对应能力要求和证据形成状态。
- **评分原因与证据**：只解释某个能力为什么得到当前等级和分数，并定位到相关问答片段。

未形成证据的过渡问题、边界试探和结束轮次仍会出现在完整面试记录中，但不会被伪装成评分证据。

## 数据与后端边界

现有真实面试链路已经持久化 `InterviewTurn`，每轮包含 `question`、`answer`、`question_mode`、`primary_requirement_id`、`asked_at` 和 `answered_at`。本次不修改 Supervisor、动态路由或答案分析逻辑。

报告投影新增 `interview_transcript` 字段，每项包含：

- `turn_id`
- `sequence_number`
- `question`
- `answer`
- `question_mode`
- `requirement_id`
- `requirement_label`
- `asked_at`
- `answered_at`
- `evidence_ids`
- `evidence_status`：`supporting | limiting | mixed | none`

后端从同一份 Plan、InterviewTurn 和 Evidence 生成该投影，严格校验 Turn、Requirement 和 Evidence 的引用关系。演示报告使用冻结 Turn，真实报告使用候选人实际 Turn；两者共用完全相同的 ViewModel 和前端组件。

缺失回答时显示“未提交回答”，不生成替代文本；关联数据无效时后端继续失败关闭，不向前端返回不可追溯结论。

## 前端组件

### 完整面试记录

新增默认收起的“完整面试记录”章节，位于能力雷达和匹配边界之后、评分原因之前。展开后使用纵向轮次列表：

- 左侧显示轮次序号、题型和能力名称。
- 主区先显示面试问题，再显示候选人完整回答。
- 底部仅显示证据状态和证据数量，不在此处重复评分原因。
- 有证据的轮次可跳转到对应证据抽屉。

### 雷达与匹配边界

响应式分层调整为：

- `> 1100px`：雷达和匹配边界左右并排。
- `<= 1100px`：两个模块上下排列，雷达占满内容宽度。
- `<= 780px`：继续上下排列，雷达标签最小 14px，详细内容默认收起。

雷达标签在桌面端为 15–16px，边界点视觉半径至少 8px，交互热区至少 44px。点、标签和右侧能力行触发同一个选择事件。

## 动态光晕

页面首次显示雷达时，六个边界点按顺序播放柔和光晕：

- 每个点的启动延迟递增，形成沿雷达边界移动的视觉引导。
- 完整序列只播放两轮，之后停留为清晰的静态点。
- 悬停或选中时，当前点显示稳定光晕，对应轴线、标签和能力行同步强调。
- 光晕使用橙色品牌强调色，不使用高频闪烁。
- `prefers-reduced-motion: reduce` 时禁用入场光晕动画，保留静态边框和选中态。

## 错误与空状态

- 没有 Turn 时，完整面试记录显示“暂无可展示的面试轮次”。
- Turn 没有回答时显示“未提交回答”。
- Turn 没有 Evidence 时标记“未形成评分证据”，不按 0 分处理。
- 证据引用无效时报告投影拒绝构建，保持现有的失败关闭语义。

## 验收标准

1. 主演示的六轮问题和六个完整回答均可在“完整面试记录”中查看。
2. 真实评估报告使用同一组件展示实际 InterviewTurn，不读取冻结演示数据。
3. “评分原因与证据”仍只展示与分数有关的证据，不复制完整转录。
4. 840px、960px、100px、1440px 和 390px 视口下雷达标签不越界，雷达与匹配边界不压叠，页面无水平滚动。
5. 六个雷达点播放两轮依次光晕并停止；减少动画模式下不播放。
6. 鼠标、键盘均可选择雷达维度，并打开正确的证据抽屉。
7. 后端投影测试、API 测试、前端组件测试、TypeScript 构建和多视口浏览器验收全部通过。

## 非目标

- 不修改面试题生成策略、Supervisor 决策或评分公式。
- 不为演示和真实评估维护两套前端组件。
- 不调用付费模型，不修改 API 密钥或运行环境配置。
- 不把未形成证据的回答自动解释为能力缺失。
